# 环境熟悉实验报告

**项目：** llmOS（面向大模型推理优化的操作系统级任务）
**阶段：** 任务书第一阶段「环境熟悉（2 周）」
**环境：** Windows 11 + PowerShell 5 · RTX 5060 8 GB（WDDM）
**完成人：** 郭彦诚、何祉悟

## 1 实验目的

在写任何业务代码前，先验证四件事：① 仿真内核可在无 GPU 的纯 Python 环境独立运行；②
每个实验都能由一条命令产出结果与图；③ 结果可复现（同 seed 同 digest 同数字）；④
前后端联调链路可用。这四条对应技术方案 §1.2「真实 GPU 失败不影响主交付」的前提条件。

## 4 四个验证实验

### 4.1 单元测试与覆盖率

```
46 passed
TOTAL  1316 statements  89 missed  93.24%
Required test coverage of 70% reached.
```

结论：门禁 `--cov-fail-under=70` 生效，覆盖率留有余量。

### 4.2 全量实验一键产出

```powershell
cd backend
python scripts\run_ab.py
```

- 13 个实验（E1–E13）全部 `exit 0`，耗时约 1 分钟；
- 产出 **13 个 JSON + 16 张 PNG**（含新增 `E2_blocks`、`E7_overlap`、`E10_share`、`E12_scale`）；
- 每个结果都带 `config_digest=281e75ca8018`、`seed=42`。

### 4.3 可复现性

同一 seed 连续两次运行，E1/E4/E7/E9 的数字逐位相同（JSON 直接 diff 无差异），
`test_golden_w1_e4_repeatable` 与 `test_e1_e7_e9_have_digest_and_two_columns`
把该性质固化为回归测试。时钟用 `heapq` + 自增 `seq` 打破同分平局，不依赖线程调度顺序。

### 4.4 前后端联调

## 5 遇到的问题与处理

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| PowerShell 调用 Vite | `Invoke-WebRequest` 报 "Object reference not set" | 改用 `curl.exe`，确认是 PS 5 与 dev server 的兼容问题，非应用缺陷 |
| 本机无 MySQL | 启动即连接失败 | 改为"能连则用、否则回退 `backend/data/llmos.sqlite3`"，并在 health 中暴露 `db` 字段 |
| 终端中文乱码 | `Invoke-RestMethod` 输出乱码 | 终端编码问题；浏览器与 JSON 均为 UTF-8，UI 显示正常 |
| GPU 超显存不报错 | Windows WDDM 下回溢主机共享内存 | 真机脚本以 nvidia-smi 物理显存的 0.98× 作为"装得下"阈值 |

## 6 阶段结论

**对应任务书阶段一要求：**「完成开发环境部署以及至少任务调度以及内存管理实验；提交实验报告及实验代码」。
本报告的映射为：内存管理实验 = E1（连续预占 vs 分页，`results/E1.json`）；任务调度实验 = E4
（静态批 vs 持续批，`results/E4.json`）；实验代码即 `backend/` 全部源码（`pytest` + `run_ab.py` 可复现）。

1. 环境满足"零 GPU 可完成主交付"：13 个实验、46 个测试、前端构建全部在纯 CPU 路径完成。
2. 可复现性由 `config_digest + seed + 黄金 trace 回归` 三重保证。
3. 真实 GPU 是可选增强：`adapters/` 与 `gpu_results/` 完全隔离，失败不阻塞答辩主链路。
4. 进入下一阶段（系统设计）的前置条件已满足。
