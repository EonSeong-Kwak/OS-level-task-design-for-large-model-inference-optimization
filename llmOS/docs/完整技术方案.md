## 1  项目背景与目标

### 1.1  问题陈述

大模型推理服务在运行时呈现出与传统操作系统高度同构的资源矛盾：大量并发请求竞争有限的 GPU 算力与显存；KV Cache 随自回归生成只增不减且长度事先未知；超大模型权重无法一次性装入单卡；多租户共享时既要隔离又要提高承载密度。工业界的 vLLM PagedAttention、Continuous Batching、权重卸载与 GPU 虚拟化（MPS/MIG），本质上是把操作系统中已经成熟的分页、调度、异步 I/O 与超卖思想，迁移到了推理这条新的 workload 上。

本方案不把四个任务做成互不相关的四份作业，而是由我独立建设一套名为 **llmOS** 的推理操作系统内核：用同一套离散事件时钟驱动内存管理、进程调度、存储栈与虚拟化四个子系统，使一次推理请求能够穿过完整的 OS 路径，并在统一指标总线上给出可复现的量化对比。90% 工作量在本地仿真器完成，仅在最后 1–2 周用 Colab / Kaggle / AutoDL 对 1–2 个关键机制做真实性背书，满足“零本地硬件”的约束。

### 1.2  建设目标

**功能性目标**

- 实现 KV Cache 分页内存管理：块分配、页表翻译、按需扩页、写时复制、LRU 换出。
- 实现持续批处理调度器：静态批基线、迭代级组批、FCFS / SJF / 抢占 / 公平队列，并区分 Prefill 与 Decode。
- 实现权重预取与计算-I/O 重叠运行时，以及类 cgroups 的算力份额与显存硬上限。
- 实现 GPU 虚拟地址空间、时间片复用、显存超卖、balloon 回收与越界拦截。

**非功能性目标**

- 仿真层纯 Python 3.10+，一键复现；单测覆盖率不低于 70%。
- 所有结论必须来自同一 trace、同一随机种子下的基线 vs 优化对比，禁止只展示优化后的绝对数。
- 四个子系统通过冻结的接口契约集成，由我按模块顺序实现并做自测回归。
- 真实 GPU 实验失败不影响主交付：仿真结果本身构成可答辩系统。

### 1.3  非目标

- 不从零实现 CUDA Attention kernel，不维护完整 vLLM 分支。
- 不以刷榜为目的调参；不以不可复现的云端环境作为唯一证据。
- 不把四个任务做成四套互不相通的全局变量脚本。

### 1.4  成功判据

| 维度 | 最低可答辩标准 | 加分标准 |
| --- | --- | --- |
| 系统联通 | 一条请求能依次经过调度 → 配额 → VMM → KV 分页 | 多租户 + 超卖 + 换出同时在线 |

## 2  操作系统原理映射

推理服务是一个多道程序系统：请求类比进程，KV Cache 与权重类比地址空间中的数据与代码，GPU 类比 CPU，NVMe / CPU / HBM 类比存储层次。四个任务分别对应 OS 四大子系统，本方案在实现层保持这一映射，避免滑向“纯算法调参”。

| 任务 | OS 子系统 | 核心矛盾 | 经典机制（必须实现） |
| --- | --- | --- | --- |
| 一、KV 分页 | 虚拟内存 | 显存碎片与按最大值预占浪费 | 分页、页表、demand paging、COW、置换、块分配器 |
| 二、持续批处理 | 进程调度 | GPU 空闲与尾延迟、饥饿 | PCB 状态机、FCFS/SJF/RR/MLFQ、抢占、公平队列 |
| 三、预取 + 配额 | I/O 与资源管理 | 搬运 stall 与租户争用 | 异步 I/O、双缓冲、预取、页缓存、cgroups 配额 |
| 四、GPU 虚拟化 | 虚拟化 | 单卡租户数 vs 隔离 | GPA/HPA、超卖、页错误、balloon、时间片、越界防护 |

量化直觉（作为设计预期，最终以实验为准）：分页使 KV 从“按 max_tokens 预占”变为“按实际生成占用”；持续批处理消除静态批中短请求被长请求拖死造成的空泡；计算-I/O 重叠可将 stall 从 30% 量级压到个位数；超卖用时间换空间，单卡逻辑承载可到 1.5×–3×，代价是换入换出延迟。

## 3  总体架构

### 3.1  分层与数据流

llmOS 采用单时钟、多子系统的微内核式仿真：所有时间推进由 `DiscreteEventSim` 独占。上层只投递事件，下层只响应接口调用。请求对象 `Request` 作为贯穿全栈的 PCB。

```
Workload(Trace / Poisson)
        |  Arrival 事件
        v
 DiscreteEventSim  (now, 优先队列, schedule / run / step)
        |
        +--> Scheduler._pick_batch()     # 任务二：决定本 iteration 集合
        |         |
        |         +--> QuotaManager       # 任务三：算力份额 / 显存硬上限
        |         +--> MPSScheduler       # 任务四：时间片与 ctx-switch 开销
        |         +--> PrefetchRuntime    # 任务三：层间搬运与 stall 记账
        |         v
        +--> PageTable.append_token()    # 任务一：逻辑 token -> KV block
                  |
                  +--> BlockAllocator     # 引用计数 / COW / LRU
                  +--> GPUVMM.access()    # 任务四：驻留、换出、隔离
        |
        v
 MetricsBus -> JSON / matplotlib / 甘特图 / overlap 图
```

一次 decode iteration 的标准时序：时钟弹出 `DecodeTick` → 调度器选出 batch → 配额与 MPS 确认本片可运行租户 → 对每个请求推进一个 token → 页表 append 可能触发 page fault → 分配器向 VMM 申请驻留页 → 预取运行时并行发起下一层权重搬运并累计 stall → 完成者离队、空槽立即填入就绪队列（持续批）。

### 3.2  模块职责与禁止越权

| 模块 | 允许做 | 禁止做 |
| --- | --- | --- |
| DiscreteEventSim | 维护 now 与事件堆、保证因果序 | 包含任何调度或分配策略 |
| Scheduler | 入队、选批、抢占、统计 TTFT/吞吐 | 直接操作物理页或 NVMe 带宽 |
| QuotaManager | 份额、硬上限、OOM 拒绝 | 决定谁先 decode |
| PrefetchRuntime | 计算/搬运重叠与 stall 度量 | 修改页表映射 |
| GPUVMM | 驻留、换出、balloon、越界拦截 | 理解 token 或 Attention |
| PageTable / Allocator | 逻辑序列 ↔ KV 块、COW、碎片指标 | 实现租户时间片 |

**实现对照（已按表落地，禁止越权写进对方内部）：**

| 模块 | 代码位置 | 越权防护 |
| --- | --- | --- |
| 时钟 | `llmos/sim/clock.py` | 只有 `schedule`/`step`/`run`；`kind=DecodeTick` 仅为事件标签 |
| 调度器 | `task2_scheduler/scheduler.py` `_decode_tick` | 只调用页表 / 配额 / MPS / 预取接口；不 import `GPUVMM`、`BandwidthModel` |
| 配额 | `task3_runtime/quota_manager.py` | `alloc_mem` / `allow_slice` 只返回是否可跑；decode 顺序由调度器 + MPS 决定 |
| 预取 | `task3_runtime/prefetch_runtime.py` | `tick(sim)` 记 stall 并 `schedule(DmaComplete)`；不碰页表 |
| VMM | `task4_gpu_virt/gpu_vmm.py` | 只认 tenant/VPN/PPN |
| 分页 | `page_table.py` + `kv_block_allocator.py` | `ensure_resident` 向 VMM 申请驻留；时间片在 `MPSScheduler` |

编排层（调度器）可以**调用**各模块，但不得把物理页分配、NVMe 带宽、页表映射写进自己的策略函数。`BlockAllocator.tenant` 仅在 `step` 前切换，供 VMM 隔离，不算调度器操作物理页。`experiments.py` 是实验总装，允许直接打 VMM/预取做 E7/E9/E10，不属于 Kernel 互越权。

### 3.3  仿真与真实引擎解耦

系统分为三层：Workload 层只产出请求轨迹；Kernel 层（本方案主体）只消费抽象资源代价（step_cost、带宽、页大小）；Adapter 层可选地把同一轨迹接到 HuggingFace transformers 或 vLLM，用于核对“分页降低 OOM / 持续批提高吞吐”的方向是否与仿真一致。Adapter 失败不得阻塞 Kernel 交付。

## 4  子系统详细设计

### 4.1  任务一：KV Cache 分页内存管理

#### 4.1.1  基线与优化定义

**基线**采用连续预占：序列创建时一次性申请 `ceil(max_tokens / block_size)` 个块，并在物理上视为必须连续的大段。该模型同时制造内部碎片（实际生成远小于上限）与外部碎片（多序列争抢连续大洞），并无法在 beam / 并行采样间共享前缀。

**优化**采用 PagedAttention 同构设计：物理层是固定大小的 KV block 池（默认 `block_size=16` 个 token）；每个序列维护页表，将逻辑 token 下标映射为 `(block_id, offset)`。生成过程按需分配；fork 时只增加引用计数；写路径在 `ref_count>1` 时拷贝分裂；池耗尽时按 `last_access` 做 LRU 换出到 HostSwap（CPU 内存模拟区）。

#### 4.1.2  数据结构

```python
@dataclass
class Block:
    block_id: int
    ref_count: int = 0
    is_shared: bool = False
    last_access: float = 0.0
    resident: bool = True          # False 表示已换出到 HostSwap
    swap_location: Optional[int] = None

class BlockAllocator:
    # free_stack: 空闲块栈，allocate/free 摊还 O(1)
    # blocks: List[Block]
    # host_swap: 仅记账容量，不存真实张量

class PageTable:
    # seqs: Dict[seq_id, List[block_id]]
    # token_len: Dict[seq_id, int]
```

分配器第一期使用“空闲栈 + 引用计数”。伙伴系统作为加分项：仅当需要演示外部碎片的经典曲线时启用，不作为联调阻塞项。

#### 4.1.3  关键算法

**（1）按需扩页 `append_token(seq_id)`**

- 若 `token_len % block_size != 0`：只增加逻辑长度，写当前块 offset。
- 否则视为 KV page fault：`allocate(1)`。若空闲不足，`steal_for_eviction(now)` 选择 `ref_count==1` 且 `last_access` 最小的驻留块换出。
- 每次 append / translate 末尾调用 `ensure_resident`：块不在驻留则向 `GPUVMM.access` 申请物理页（VMM 侧 page fault）；换出块仍在空闲栈则可换入恢复。
- 换出后仍不足则抛 `AllocError`，由调度器将该请求标记失败（计入 OOM 比例）。

**（2）写时复制 `fork(src_seq)`**

- 新序列页表复制源序列的 `block_id` 列表，对每个块 `ref_count+=1`，`is_shared=True`。
- 任一方再 append 且将写满新位置时，若目标块 `is_shared`：分配新块、拷贝元数据、源块 `ref_count-=1`。

**（3）指标**

- `utilization` = 实际占用 token 当量 / 物理池 token 当量。
- `fragmentation_ratio`：内部碎片单独统计 last-block 空洞；外部碎片看空闲块无法满足一次 `allocate(n)` 的比例。
- COW 收益 = 共享块数 / 若无共享应占块数。

#### 4.1.4  与 VMM 的衔接

`BlockAllocator.allocate` / `ensure_resident` 对每个需要驻留的 block 调用 `GPUVMM.access(tenant, vpn, write)`。VMM 负责物理页驻留与超卖换出。这样任务一的 OOM 与任务四的超卖成为同一资源池上的两种视图。单测阶段允许不注入 `vmm`（恒驻留）隔离任务一。

### 4.2  任务二：持续批处理请求调度器

#### 4.2.1  请求 PCB 与两阶段代价模型

`Request` 即进程控制块。状态：`WAITING`（就绪）、`RUNNING`（本 iteration 在批内）、`PREEMPTED`（被踢出批但 KV 仍在分页器）、`FINISHED`。调度指标全部从 PCB 时间戳推导，禁止事后用全局计数器“估一个吞吐”。

- Prefill 视为一次长 CPU burst：`cost_prefill = alpha * prompt_len`
- Decode 每步视为短 burst：`cost_decode = beta * f(batch_size)`
- 上下文切换开销 `cost_cs` 只在请求进出 batch 时计入

正因为 KV 常驻（或由 VMM 决定是否换出），iteration 级调度才划算。

#### 4.2.2  静态批 vs 持续批

- `StaticBatchingScheduler`：凑满 `batch_size` 才启动；批内任一请求未结束则整批占用 GPU；短请求完成后槽位空转。作为全部对比的基线。
- `ContinuousBatchingScheduler`：每个 DecodeTick 重新 `_pick_batch`。完成者立即释放槽位，WAITING 队头填入。GPU 忙闲比 = 有非空 batch 的时间 / 仿真时长。

#### 4.2.3  策略实现规格

| Strategy | 选批规则 | 抢占 | 预期教学现象 |
| --- | --- | --- | --- |
| FCFS | 按 arrival_time 填满槽位 | 否 | 吞吐高于静态批；长请求可占槽 |
| SJF | 按剩余生成长度升序 | 否 | 平均周转下降；长请求饥饿 |
| PREEMPTIVE | 优先级；时间片用尽踢到 PREEMPTED | 是 | TTFT 改善；需计 ctx 开销 |
| MLFQ | 用满片降级，让出升入高队列 | 是 | 兼顾响应与吞吐（加分） |
| FAIR | 租户令牌桶 / 份额加权 | 可 | P99 方差下降，防跨租户霸占 |

饥饿定义：等待时间超过阈值 θ（默认 10× 平均 decode 时长）仍未进入 batch 的请求占比。FAIR 必须把该指标压到配置上限以下，否则视为公平策略未完成。

#### 4.2.4  调度主循环

工作发生在时钟弹出的 `DecodeTick`（本片含 Prefill 时标签为 `PrefillTick`）上，而不是先 sleep 再 `on_tick`。

```python
def _decode_tick(self):
    self._reap_finished()
    batch = self._pick_batch()
    if not batch:
        self.sim.schedule(self.idle_tick, self._decode_tick, kind="DecodeTick")
        return
    admitted, mps_extra = self._confirm_slice(batch)  # Quota.allow_slice + MPS 本片租户
    stall = self.prefetch.tick(self.sim) if self.prefetch else 0.0
    cost = self._iteration_cost(admitted) + stall + mps_extra
    for req in admitted:
        req.step(self.sim.now)
        self.page_table.append_token(req.seq_id)  # 可能 ensure_resident → VMM
    self._reap_finished()
    self._pick_batch()  # 持续批：空槽立即填入
    self.sim.schedule(cost, self._decode_tick, kind="DecodeTick")
```

`_maybe_schedule` 仅作为 `_decode_tick` 的别名，供驱动循环在堆空时补一次节拍。

### 4.3  任务三：权重预取、重叠与多租户配额

#### 4.3.1  带宽悬崖模型

`BandwidthModel` 固化三级带宽：NVMe 3.5 GB/s、CPU↔GPU(PCIe) 16 GB/s、GPU HBM 800 GB/s。`transfer_time(size, src, dst)` 取路径上的瓶颈带宽。禁止在实验中途修改这些常数；若做灵敏度分析，必须单独成节并列出配置哈希。

层权重以列表 `layer_weights_gb` 输入。默认构造一个“前层较小、后层均匀”的合成模型，使预取收益可见，又不必绑定真实 70B 参数文件。

#### 4.3.2  双缓冲与 stall 定义

`PrefetchRuntime` 对 `decode_step(layer)` 并发执行：计算当前层（模拟 GPU 忙碌）与预取 `layer+1 … layer+lookahead`。

- I/O stall = `max(0, prefetch_remaining - compute_time)`
- `io_stall_ratio` = 累计 stall / 累计（compute + stall）
- 串行基线 `lookahead=0`，即算完再搬

权重页缓存采用 LRU，容量为 `cache_layers`。命中则搬运时间为 0。ARC 作为加分淘汰策略。缓存占用计入租户显存配额，`alloc_mem` 失败则该层必须走 NVMe 路径或拒绝运行。

#### 4.3.3  类 cgroups 配额

`TenantQuota` 含 `gpu_compute_share`（相对权重）与 `gpu_mem_gb`（硬上限）。

- `alloc_mem` 超限返回 False，由调用方转为 OOM，不得静默借用其他租户。
- `compute_slice(tenant, tick)` 按份额分配本 tick 可用 GPU 时间。
- `is_isolated` 自检：任何租户累计显存不超过自身上限，且全局之和不超过物理容量。

调度器在 `_pick_batch` 中必须查询配额：份额用尽的租户本 tick 不能被选入 batch。由此任务二与任务三在控制面上闭合。

### 4.4  任务四：GPU 虚拟化与显存超卖

#### 4.4.1  地址空间与页错误

每个租户拥有独立虚拟页表。`create_tenant(tenant, vmem_pages)` 允许 `vmem_pages > phys_pages`，从而形成超卖。`access(tenant, vpn, write, now)` 流程：

1. vpn 越界：记 isolation_violation 尝试次数，拦截并抛 `IsolationError`，不得分配。
2. 未驻留：page fault；若有空闲 PPN 则建立映射；否则 LRU 换出其他租户冷页到主机 swap。
3. 写访问置 dirty；换出脏页计入额外 `swap_write` 时间。
4. `oversubscription_ratio` = 各租户虚拟页之和 / 物理页数。
5. `isolation_violation_rate` = 未拦截次数 / 越界尝试次数，验收标准为 **0**。

#### 4.4.2  Balloon 与 MPS

- `balloon_reclaim(tenant, pages)` 从该租户选择未访问或可丢弃的空闲虚拟页，解除驻留并归还物理池。
- `MPSScheduler` 按 share 加权轮转时间片。`run_slice` 扣除 `ctx_switch_cost`（默认 0.5 ms 量级，可配置）。
- Jain 公平指数：令 \(x_i\) 为租户 i 的归一化服务时间（实际服务 / 份额），\(J = (\sum x)^2 / (n \sum x^2)\)，越接近 1 越公平。

## 7  工程实现方案

### 7.1  技术选型

时钟用标准库 `heapq` 实现优先队列，不强制依赖 simpy。`PrefetchRuntime` 用 asyncio 表达并发搬运，在离散事件中把 await 点翻译为 `schedule(delay, callback)`，避免真实睡眠。统计可用纯 Python，热点循环若需要再用 numpy。测试用 pytest；覆盖率用 pytest-cov。配置用 PyYAML。

### 7.2  质量门禁（个人自检）

- 每个模块合入前：`pytest -q --cov=llmos --cov-fail-under=70`。
- 黄金 trace（固定 seed 的 W1 子集）指标波动超过 1% 视为回归。
- 改分配器后必须重跑任务一单测 + E1；改调度后必须重跑 E4。
- 禁止提交真实 API Key、云端账号与未脱敏日志。

### 7.3  确定性

离散事件不得依赖线程调度顺序。所有随机只来自 `random.Random(seed)`。asyncio 路径必须把完成时间写入事件队列，而不是依赖 Task 完成先后。同一配置在任意机器上数字一致。

## 11  实现硬约束（自审清单）

- `PageTable.translate` 必须对非法 `seq_id` / 越界 `logical_idx` 失败，不得返回随机块。
- `free` 只有在 `ref_count` 降到 0 时才把块放回空闲栈，防止 COW 下提前回收。
- `steal_for_eviction` 不得驱逐 `ref_count>1` 的共享块，除非先分裂。
- Static 与 Continuous 必须共享同一 `Request.step` 与同一代价函数，对比才公平。
- FAIR 的令牌发放与 MPS 的份额必须用同一 tenant 配置源，避免两套份额。
- Prefetch 的 stall 只统计“计算线程因数据未就绪而等待”的时间，不得把 DMA 忙碌算进 GPU 有效算力。
- `GPUVMM.isolation_violation_rate` 在故意越界测试中分母 > 0、分子必须为 0。
- `run_ab` 默认打印基线与优化两列，缺任一列视为评测脚本不合格。
