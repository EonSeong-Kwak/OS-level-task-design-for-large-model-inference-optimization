| | 利用率峰值 | 碎片峰值 | 换出次数 | 并发峰值 | 活跃序列峰值 | OOM 率 | 吞吐 |

| 分页 | 0.999 | 0.469 | 812 | 6 | 6 | **0** | 2.165 |

分页把 **OOM 从 45.5% 压到 0**，并发峰值 **+200%**、活跃序列 **+500%**、利用率峰值 **+38.1%**；

末尾块存在块内碎片，空闲链也更分散；本负载下收益来自消除 OOM 与提升并发，而非碎片指标，

## 附录：真实 GPU 方向对照（G1 → E1）

按技术方案 §6.3「云端对照（非阻塞）」与 `系统设计文档.md` §7 执行；脚本 `adapters/gpu_g1.py`，产物 `gpu_results/`，**不 import 仿真内核、不与 `results/E*.json` 混表，只比方向**。

**环境（2026-11-16 复跑，证据 `gpu_results/nvidia-smi.txt`）：** NVIDIA RTX 5060 8 GB（WDDM）、Qwen2.5-0.5B fp16（权重 1.0 GB）、torch 2.8.0+cu128、transformers 5.3.0。

**G1 设计：** 每个序列实际只跑 32+32 token（W1 短对话），静态侧 `StaticCache` 按 max_tokens=2048（W2 长上下文上限）预占整条 KV，动态侧 `DynamicCache` 按需增长——复刻 E1「按最大值预占 vs 按实际占用」。

| 指标 | 静态预占 | 按需增长 |
| --- | --- | --- |
| 最大可承载并发 N | **192**（峰值 7.72 GB） | **640**（峰值 7.75 GB） |
| 越界点 | N=256 即超过 8 GB 物理显存（WDDM 回溢共享内存），N=640 真实 CUDA OOM | 扫到 N=640 仍在物理显存内 |
| 并发提升 | — | **≥ 3.33×** |

**方向结论：** 真实引擎上「预占→OOM、按需→承载更高」与仿真 E1（OOM 率 0.45→0、KV 峰值利用率显著上升）同向，`verdict=CONSISTENT_WITH_SIM_E1`。图：`gpu_results/g1.png`，明细：`gpu_results/g1.json`。

**代价参数校准（`gpu_results/calibration.json/.png`，灵敏度附录，不回写冻结配置，§4.3.1）：** 采用总耗时线性拟合 T = 固定开销 + 边际速率×长度（而非会被固定开销扭曲的 ms/token 比值）：prefill 拟合为 **2.48 ms + 0.122 ms/token**（R²=0.92），边际速率约为冻结 alpha（0.02 ms/token）的 6×；decode 拟合为 **29.5 ms + 0.20 ms/批**（R²=0.39，斜率接近 0）——桌面卡 eager 模式下每步 ~30 ms 的 kernel 发射地板主导，batch 维度近乎平坦，与数据中心级线性代价模型形态不同，差异如实保留。实测 KV 为 12,288 B/token（24 层 ×2 KV 头 ×64 ×2 路 ×fp16），仿真块模型为 0.005 GB/16 token ≈ 3.13×10⁵ B/token（约 25×，对应 ~70B 级 GQA 模型）。
