## RV-01 W3 · 块分配器与页表首版

- **提交 / 审查：** 郭彦诚 / 何祉悟
- **对照条款：** §11-1、§11-2；§5.1 冻结接口
- **发现问题：**
  1. `free(block_ids)` 直接把块压回空闲栈，未检查 `ref_count`——共享块会被提前回收。
  2. `translate()` 对越界 `logical_idx` 返回 `None`，上层继续用旧块号，等价于"返回随机块"。
- **结论：** 打回。
- **整改：** free 改为 `ref_count -= 1` 且为 0 才回收；translate 对非法 seq / 越界 idx 抛 `KeyError` / `IndexError`。
- **复审证据：** `test_free_only_when_refcount_zero`、`test_translate_contract`、`test_translate_rejects_oob`。

## RV-02 W4 · COW 分叉与 LRU 换出

- **提交 / 审查：** 何祉悟 / 郭彦诚
- **对照条款：** §11-3；E2 / E3
- **发现问题：** `steal_for_eviction` 的候选集只按 LRU 排序，未过滤 `ref_count > 1`，会驱逐仍被两个序列引用的前缀块。
- **结论：** 打回。
- **整改：** 候选只取 `ref_count == 1`；需要驱逐共享块时先分裂（COW）再入候选。
- **复审证据：** `test_kv_cow_and_lru_eviction`；E2 物理块数 = 6（4 分支）+ 增量。

## RV-03 W4 · E1 基线构造

- **提交 / 审查：** 郭彦诚 / 何祉悟
- **对照条款：** §11-4；§6.2 E1 通过线
- **发现问题：** "连续预占"基线在池满后仍允许 LRU 换出，实际上变成了分页策略，导致 E1 对比不公平（基线 OOM 被掩盖）。
- **结论：** 打回。
- **整改：** contiguous 模式禁止驱逐，池满即抛 `AllocError`。
- **复审证据：** E1 基线 `oom_ratio = 0.4545`，优化后 `0.0`，与报告一致。

## RV-05 W6 · FAIR 与租户份额

- **提交 / 审查：** 郭彦诚 / 何祉悟
- **对照条款：** §11-5；E6 通过线
- **发现问题：**
  1. FAIR 令牌按 `1/租户数` 平均发放，未使用 `TenantQuota.gpu_compute_share`，与 MPS 形成两套份额。
  2. MPS 时间片窗口按排他方式占用，导致 FAIR 后 P99 反而变差（与通过线相反）。
  3. `hunger_threshold` 按绝对秒数解释，换负载后阈值失效。
- **结论：** 打回。
- **整改：** FAIR 改为槽位准入 + 份额加权；MPS 窗口只记账不排他；饥饿阈值改为 `hunger_threshold_x = 10` 倍数语义。
- **复审证据：** E6 verdict「FAIR 压低跨租户 P99 方差」，5 个 seed 均成立，方差 −85%。

## RV-06 W7 · 预取 stall 口径

- **提交 / 审查：** 何祉悟 / 郭彦诚
- **对照条款：** §11-6；E7 通过线
- **发现问题：** `effective_compute_ratio` 的分母含 DMA 忙碌时间，等价于把 IO 时间算作 GPU 有效算力，导致 E7 出现"优化后 stall 变高"的反向结果。
- **结论：** 打回。
- **整改：** stall 只计"计算等待数据就绪"；`io_stall_ratio = stall/(compute+stall)`，DMA 并行时间不计入分母。
- **复审证据：** E7 `io_stall_ratio` 0.9346 → 0.8169，缓存命中 0.667；三档单调。

## RV-07 W8 · 配额块粒度

- **提交 / 审查：** 郭彦诚 / 何祉悟
- **对照条款：** §5.4 `alloc_mem`；E8
- **发现问题：** 配额按 token 数换算显存，忽略块对齐，低估计费导致硬上限失效（越界申请未被拒）。
- **结论：** 打回。
- **整改：** 统一按 `ceil((prompt+gen)/16) × kv_block_gb(0.005GB)` 预留，粒度与分配器一致。
- **复审证据：** E8 越界申请返回 `QuotaOOM`，邻租户延迟稳定。
