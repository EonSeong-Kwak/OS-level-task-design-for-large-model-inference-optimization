## 第 1 周：仓库骨架与环境疏通

- **目标**：确定四任务目录边界，跑通"空时钟 + 空负载"的最小闭环。
- **完成**：`backend/llmos/{sim,task1_kv_memory,task2_scheduler,task3_runtime,task4_gpu_virt,workloads}` 建立；
  FastAPI + SQLite 回退链路打通；`configs/default.yaml` 按附录 A 写入冻结常数。
- **产出**：仓库可 `pip install -r requirements.txt` 后直接 `uvicorn` 启动；README 一键说明。
- **风险**：MySQL 本机未装 → 采用"能连则用、连不上回退 SQLite"策略，不阻塞开发。

## 第 2 周：离散事件时钟、合成负载与指标总线

- **目标**：时钟确定性 + 负载可复现 + 指标可聚合。
- **完成**：`DiscreteEventSim` 用 `heapq`，同分事件用自增 `seq` 打破平局，杜绝线程顺序影响；
  `synthetic_poisson(seed, ...)` 仅用 `random.Random(seed)`；W1–W3 三档负载（含 W2 长 prompt、W3 突发）定型。
- **产出**：黄金 trace 雏形；首版单元测试（时钟、负载、分配器）。
- **风险**：早期用全局 `random` 导致重跑不一致 → 改为显式传 `Random(seed)`，并加入 `test_golden_w1_e4_repeatable` 做确定性回归。

## 第 3 周：任务一——块分配器与页表骨架

- **目标**：冻结接口先落地，再谈优化。
- **完成**：`BlockAllocator(num_blocks, block_size)` / `allocate` / `free` / `fork` / `steal_for_eviction`
  / `fragmentation_ratio` / `utilization`；`PageTable.new_sequence / append_token / translate / fork / free`；
  `translate` 对非法 seq、越界 idx 明确抛错（不返回随机块）。
- **产出**：`test_translate_contract`、`test_free_only_when_refcount_zero`、`test_refcount_free_contract`。
- **风险**：连续预占与分页两套代码分支容易"各写一套代价" → 统一到同一 `Request.step`。

## 第 4 周：任务一——COW、LRU 换出与 E1/E2/E3

- **目标**：让"分页优于连续预占"在压力场景下成立。
- **完成**：前缀共享（fork 后 ref_count+1，写时分裂）；LRU 换出只挑 `ref_count == 1` 的块；
  `steal_for_eviction` 过滤共享块。E1 结论：**OOM 率 0.45 → 0**；E2 块数接近 1/分支数 + 增量；
  E3 池 2048（0 换出） vs 288（全完成、744 换出、0 失败）。
- **产出**：`results/E1/E2/E3.json` + 对应图。
- **风险**：早期 contiguous 模式允许 LRU 驱逐，导致"连续预占"名不副实 → 改为池满即 `AllocError`。

## 第 5 周：任务二——静态批 vs 持续批

- **目标**：把调度差异做公平对比。
- **完成**：`StaticBatching` 与 `ContinuousBatching` 共用 `_iteration_cost` 与 `Request.step`；
  持续批"完成者离队、空槽填入"；E4 吞吐与 GPU 忙闲比上升，TTFT 改善。
- **产出**：`results/E4.json` + 甘特数据（前端可交互查看空泡）。
- **风险**：静态批若按最大序列长度计费会人为拉低吞吐 → 统一按每迭代实际 batch 计费，并在文档写明。

## 第 6 周：任务二——SJF/抢占、FAIR 与 E5/E6

- **目标**：暴露饥饿，并用公平调度收敛尾部延迟。
- **完成**：FCFS / SJF / 抢占三策略；FAIR 改用**槽位准入按份额加权**，MPS 时间片窗口只记账不排他；
  份额统一来自 `TenantQuota.gpu_compute_share`；饥饿阈值语义改为 `hunger_threshold_x: 10`（倍数）。
  E6 跨租户 P99 方差 **−85%**，5 个 seed 全部成立。
- **产出**：`results/E5/E6.json` + 租户 P99 柱状图。
- **风险**：曾出现 FAIR 让 P99 变差的反向结果 → 定位为"两套份额"与排他式时间片，按 §11-5 修正。

## 第 7 周：任务三——带宽模型、双缓冲与 E7

- **目标**：让 stall 单调下降。
- **完成**：`BandwidthModel` 三级带宽 3.5 / 16 / 800 GB/s；`PrefetchRuntime` 三档：串行、
  双缓冲（lookahead=2）、预取 + 层缓存（11 层）；stall 只计"等数据"，DMA 忙碌不计入有效算力。
  E7：stall 占比 **0.935 → 0.817**，缓存命中率 0.67；4×4 消融（lookahead × cache_layers）给出阶跃。
- **产出**：`results/E7.json` + `stall_timeline` 三系列 + 消融热力图（前端）。
- **风险**：早期把 DMA 忙时算进 GPU 有效算力，导致 E7 出现"优化后更差" → 按 §11-6 重算。

## 第 8 周：任务三/四——配额、MPS 与 E8/E10

- **目标**：硬上限可拒绝、份额可核对。
- **完成**：`QuotaManager.register / alloc_mem / compute_slice / is_isolated`；`QuotaOOM` 硬上限拒绝；
  `MPSScheduler.pick_next / run_slice / fairness_index`（Jain）。E8：越界申请被拒、邻租户延迟稳定；
  E10：1:1 vs 3:1 服务时间近似跟份额。
- **产出**：`results/E8/E10.json` + α/β 份额柱状图。
- **风险**：块粒度配额按 token 计导致低估 → 改为 `ceil((prompt+gen)/16) × kv_block_gb(0.005)` 预留。

## 第 9 周：任务四——VMM、超卖与 E9

- **目标**：逻辑页 > 物理页可运行，越界零漏拦。
- **完成**：`GPUVMM.create_tenant / access / balloon_reclaim / oversubscription_ratio /
  isolation_violation_rate`；pin/unpin/release 与脏页 `swap_write_delay`。
  E9：超卖比 1.0→5.0，拦截率 **0**，延迟单调上升（Pareto 曲线可解释）。
- **产出**：`results/E9.json` + Pareto 图；越界测试覆盖"分母>0、分子=0"。
- **风险**：越界统计在无访问时除零 → 显式返回 0 并在测试中固定两种场景。

## 第 10 周：评测总装与全量回归

- **目标**：一条命令产出全部对比与图。
- **完成**：`scripts/run_ab.py` 默认双列打印 baseline / optimized；13 个实验 JSON + PNG；
  补齐 E11（多租户并发争用）、E12（结构性微基准）、E13；`trace_loader.py` 支持离线 JSONL trace。
- **产出**：`backend/results/` 全量产物；`pytest --cov=llmos` 通过门槛。
- **风险**：手工抄数字进报告易漂移 → 报告只引用 JSON，脚本重跑即可复现。

## 第 12 周：真实 GPU 方向背书与答辩准备

- **目标**：用真实模型验证"方向一致"，不追求数字一致。
- **完成**：`adapters/gpu_g1.py` 在 RTX 5060 + Qwen2.5-0.5B（fp16）上跑 G1：
  StaticCache 预占最大并发 **192**，DynamicCache 按需 **640**（×3.33），Verdict
  `CONSISTENT_WITH_SIM_E1`；同脚本完成代价参数校准（prefill 2.48 ms + 0.122 ms/token，R²=0.92；
  decode 29.5 ms + 0.20 ms/批，R²=0.39），差异按 §4.3.1 只入附录、不回写冻结常数。
- **产出**：`gpu_results/g1.json`、`calibration.json`、两张图；评测报告附录；答辩脚本。
- **风险**：Windows WDDM 超显存会回溢共享内存而不报错 → 以 nvidia-smi 物理显存 0.98× 为判定阈值；
  Colab T4 为标准 compute 模式，同一脚本可直接复用。
